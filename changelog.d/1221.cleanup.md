`users.FindOrCreate` returns `(User, error)`, so a lookup failure and a create failure are no longer both flattened into a bare empty `User`. The error is tagged `users.ErrLookupFailed` or `users.ErrCreateFailed` and wraps the underlying DB error, giving callers and log readers a way to tell "couldn't read the existing row" from "couldn't write a new one". Hot-path behavior is unchanged: `login` and `CorrectMiles` log the error and continue keying off the zero ID, so an un-saveable user still isn't cached and the next tick still self-heals.
