Deploys and stream-watchdog transitions now land in the permanent events log. Startup records a `deploy` event naming the component and build version — only when the version changed, so pod restarts don't spam rows — and the silent-disconnect watchdog records a `watchdog_restart` event (with an `ok`/`failed` outcome) for every forced recovery plus a `watchdog_recovered` event once a recovery holds. The next outage timeline is a query over `events` instead of an archaeology dig through expired logs.
