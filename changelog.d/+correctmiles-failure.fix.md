`!givemiles` says so when a correction doesn't land, instead of posting a fabricated total and recording an event for it. `Sessions.CorrectMiles` returns `(float32, error)`; when the target's DB row can't be read or created there is no running total to report, so the reply is "Couldn't apply that right now, try again in a bit". The correction event goes in only once the correction has persisted — `events` is append-only, so an event with no matching `users` write left the miles rollups permanently diverged.
