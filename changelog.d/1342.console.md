`GET /api/user/{username}` takes an optional `?user_id=` carrying the platform's own user id, and resolves the chatter by it before falling back to the name. A viewer who renames themselves used to strand their row under the old login — the popover would open on nobody, or on whoever took the name — and the id survives that. The response's `username` reports whichever row actually answered, and the session/first-seen reads follow it rather than the name that was asked for. Chatters' rows get stamped with their id as they talk, so the id path starts answering for anyone active and the name fallback covers the rest.
